# Qnet steady-state method catalog

This catalog records the steady-state methods implemented in this repository as of
2026-09-04. It describes each method's mathematical contract and integration state;
it is not a code-quality review and does not replace the method-specific README or
validation material.

Commands below assume the repository root is the current directory. Build a C
solver first with `make -C <solver-directory>`. Python methods require Python 3;
the legacy tandem CTMC additionally requires NumPy. Paths link to the implementation
or its primary documentation.

## Read this distinction first

- **Queue process** means the original discrete-customer stochastic network. An
  exact queue-process result is exact only for the stated arrival, service,
  discipline, routing, capacity, and stability assumptions.
- **Queue approximation** still targets discrete queues, but closes or truncates
  part of the queue model. Its residual may show that its own equations were solved;
  it does not bound queue-model error.
- **Queue simulation** samples the discrete queue process. A confidence interval
  describes sampling error, not warm-up bias or a mismatch in blocking semantics.
- **SRBM/diffusion** first replaces the queue by a semimartingale reflecting Brownian
  motion (SRBM), usually under heavy traffic. An accurate solution of that SRBM is
  not an exact solution of the queue. Agreement among two SRBM solvers is a numerical
  cross-check, not independent validation of the queue approximation.
- **Certified** is reserved below for a theorem-backed statement whose stated
  assumptions were checked. A solver residual, mesh comparison, small truncation
  boundary mass, effective sample size, or held-out BAR residual is evidence, but is
  not a certificate unless the implementation says so explicitly.

may be used to derive its drift, covariance, and reflection data, but the resulting
stationary law is the SRBM law unless a separate queue-limit theorem is invoked.

## Runtime, scale, and result safeguards

- **Visible startup dependency check.** Every GUI launch checks dependencies
  sequentially and retains a green checkmark beside each available item. Missing
  items remain visible with one de-duplicated Homebrew install command and any
  separate Python-package command. Optional method add-ons are labelled as such.
  A packaged `Qnet.app` load-probes representative bundled solver components;
  a source-tree run instead checks the Homebrew formulae needed to rebuild them,
  so release users are not told to install libraries already inside the app.
- **Deterministic runtime resolution.** [`SolverRuntimeResolver.swift`](../Sources/Qnet/SolverRuntimeResolver.swift)
  searches bundled app resources first, then `QNET_SOLVER_ROOT`, a nearby
  `Qnet.app`, and finally a development source tree. Native executables must
  exist, be executable, and pass a short launch/load probe; a stale binary that
  fails in the dynamic loader is rejected and the search continues. Readable
  Python support files use the same root order. Script-backed runs additionally
  launch-probe an exact Python 3 executable, check method-specific imports such
  as NumPy, invoke that exact path with `-B`, and record it in provenance; they
  never assume that a readable script implies a usable runtime. Release builds
  include a solver-availability/dependency manifest for actionable failure messages.
- **Scale preflights.** The GUI refuses adaptive truncation when the exact Jackson
  mean lies inside the practical 200,000-state boundary, refuses a spectral
  degree whose dense basis matrix alone exceeds 2 GiB, and refuses an LP grid
  estimated above two million variables. It also estimates effective MLMC
  horizon/level/sample/replication work including the `1/gamma` path refinement,
  coordinate count, and antithetic multiplier; it uses the adaptive maximum as
  the hard sample cap and refuses runs above its vector/coordinate budgets. Unset
  LP grid/basis values and adaptive
  BAR collocation counts scale with dimension, and the finite-element dialog
  lowers its initial mesh for high-dimensional networks. Run Comparison treats
  an over-budget method as an independent skip rather than aborting other methods.
- **Failed versus partial.** A nonzero solver exit, zero usable parsed performance
  measures, no regenerative cycle, or no numerical BAR bounds is **Failed**.
  Usable estimates are **Partial** when adaptive BAR reaches maximum rank,
  regenerative simulation stops before its requested precision, truncated CTMC
  reaches its cap before heuristic convergence, adaptive MLMC reaches its
  maximum samples before its SE target, SBD uses its fallback, or a
  comparison retains some successful methods after another fails or is skipped.
  A comparison is **Failed** only if every method fails or is skipped.
- **Corrected scale fixture.**
  [`input/examples/15stationtandem.inf.bnet`](../input/examples/15stationtandem.inf.bnet)
  now contains exactly 15 station nodes (and 15 paired buffer nodes), so its name,
  dimensions, applicability decisions, and scale warnings agree.

## Concrete integration and packaging gaps

1. **The broad QBD and product-form contracts remain CLI-only.** The bundled GUI
   adapters cover exact open class-preserving FCFS M/M/c product form and the
   strict one-source, one-class, one-station M/M/1 QBD, including optional
   class-preserving feedback. General QBD level/phase blocks, closed or mixed BCMP
   populations, other BCMP disciplines, and Kaufman-Roberts shared-resource
   requests need fields that the visual `.bnet` model does not represent; their
   versioned CLIs remain the explicit integration boundary.
2. **The finite-buffer LP remains scientifically incomplete.** Its README calls the
   executable a Phase-1 orthant copy; the rectangle BAR, upper-face reflection, and
   two-sided boundary-measure work are still pending even though the GUI presents a
   finite-buffer LP action.
3. **Some rich evidence is still not typed end-to-end.** Results now ingest adaptive
   CTMC cap evidence, BAR rank/residual or bound rows, and regenerative node-level
   intervals/effective-cycle notes. The standalone CLIs also report phase laws,
   tail probabilities, certified Foster bounds, BAR cone diagnostics, regenerative
   weight diagnostics, and product-form state laws. For GUI-wired methods, the
   workspace keeps the remaining detail in raw output and types a smaller common
   station-metric subset.
4. **Input contracts are split.** `generic_ctmc`, `product_form`, and `bar_bounds`
   provide machine-readable `schema.json` files. Other new JSON methods validate a
   versioned contract in code and documentation but do not ship a schema artifact.
   Legacy solvers use several incompatible positional/text formats, including three
   finite-SRBM reflection-column conventions.
5. **Important model classes remain uncovered.** There is no general exact BAS/BBS
   network CTMC, general mixed-BCMP solver with open and closed populations sharing
   FCFS stations, general network rare-event method, non-product Markovian
   infinite-network CTMC beyond the current truncation scope, or certified
   finite-buffer queue bound. Those should not be inferred from the implemented
   tandem, loss, product-form subclass, SRBM, or heuristic results.

## Practical selection order

1. Use a closed form or exact finite/QBD/product-form solver when its assumptions
   match and its state/phase space is manageable.
2. For a quick queue-level estimate, use QNA/RQNA, finite decomposition, or adaptive
   truncation and read their diagnostics with the labels above.
3. Use seeded queue-process simulation or regenerative simulation to validate the
   queue model; vary warm-up, horizon, replications, or regenerative precision.
4. Use SRBM methods when heavy-traffic diffusion is scientifically appropriate.
   Refine their basis/mesh/rank/time horizon and compare against queue-process
   evidence before interpreting them as queue performance.
